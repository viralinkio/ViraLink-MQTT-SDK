# ViraLink-MQTT-SDK v2.0: Roadmap Checklist

Source of truth: `docs/design/ViraLink-MQTT-SDK v2 — Design Document.md`.
Each phase gets its own detailed TDD plan in this folder before work starts, and
ends at a gate: `pio test -e native` and `scripts/build_examples.sh` both pass.

## Phase 1: Core (done, 2.0.0-alpha.1)

- [x] Session state machine, backoff with jitter, CONNACK handling, AUTH_FAILED
- [x] Outbox ring: classes, control reserve, poison strikes, PUBACK-driven delivery
- [x] Correlator, router, topics, codec golden strings, JsonWriter
- [x] Telemetry and attribute publish with `{ts, values}`, UTC restamping
- [x] Scheduler (`client.every`), token-bucket drain
- [x] ESP32 esp-mqtt transport; Arduino and ESP-IDF examples build

## Phase 2: Device API modules (done; plan: `2026-10-25-phase2-device-api.md`)

- [x] Heap-free JSON reader for incoming payloads (`JsonValue`)
- [x] Codec: RPC error reply, client RPC request
- [x] Client: `cancelPending`, `lock()`, device claiming
- [x] Server-side RPC: method registry, automatic and error replies
- [x] Client-side RPC with timeout
- [x] Attribute request with timeout
- [x] Shared-attribute update handlers per key, deletion notices
- [x] Shared-attribute binding, refreshed on every Online
- [x] Client-attribute reporting on change with a minimum interval
- [x] Example `rpc_and_attributes`, README sections

## Phase 3: Gateway (done; plan: `2026-10-25-phase3-gateway.md`)

- [x] `Gateway<N>` sub-device table, connect/disconnect, replay on Online
- [x] Gateway telemetry, attributes, attribute request, RPC reply, claim
- [x] Device-name resolver wired into the drain path
- [x] Example `gateway`

## Phase 4: OTA (done; plan: `2026-10-26-phase4-ota.md`)

- [x] Checksums: MD5, SHA256/384/512, CRC32, MURMUR3_32/128 with golden values
- [x] MQTT chunk engine: request, timeout, retry, resume with new request id
- [x] `fw_state` reporting, activation and rollback (ESP32)
- [x] `fw_url` HTTPS download with Range resume
- [x] Example `ota`

## Phase 5: Provisioning, health, persistence, networks

One plan per subsystem: 5a provisioning, 5b health, 5c persistence, 5d TLS, 5e networks.

- [x] Provisioning session: access token, MQTT basic, X.509; `IKeyValueStore` (plan: `2026-10-26-phase5a-provisioning.md`)
- [x] Health attributes with configurable keys, `VL_COMPAT_V1_KEYS` (plan: `2026-10-26-phase5b-health.md`)
- [x] `IOutboxStore` with CRC16 records, torn-tail recovery, power-cut fuzzing (plan: `2026-10-26-phase5c-persistence.md`)
- [x] `ITlsProvider`, ATECC608B key: esp-tls on ESP-IDF, `AteccTlsStream` on Arduino-ESP32 2.0.x (plan: `2026-10-26-phase5d-tls.md`)
- [x] Network manager with failover and 30 s fail-back hysteresis (plan: `2026-10-26-phase5e-networks.md`)

## Phase 6: Ports and release

- [ ] Arduino QoS1 adapter: `StreamMqtt` + `ArduinoStream` landed in 5d (in-house, not lwmqtt); M0 cellular benchmark still to run
- [x] ESP8266 port: clock, ID, health, `FsStore`, firmware writer, `StreamHttp` for `fw_url`, examples in the matrix (plan: `2026-10-27-phase6a-esp8266.md`)
- [x] STM32 port: unique-ID client ID, RNG, health, `setUtcMs()`, SPI NOR flash (`W25qFlash`, `FlashKvStore`, `FlashOutboxStore`), `stm32_flash` example (plan: `2026-10-27-phase6b-stm32.md`)
- [ ] STM32 OTA through MCUboot (6c)
- [ ] AVR (Lite) port
- [ ] `ViraLinkCompat.h` 1.0.2 shim, migration guide, NOTICE
- [ ] ThingsBoard CE 3.6/4.2/4.3/lts-4.4 integration suite in Docker
