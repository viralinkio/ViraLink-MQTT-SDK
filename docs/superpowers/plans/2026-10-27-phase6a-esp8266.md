# Phase 6a: ESP8266 Port Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** ESP8266 (Arduino core 3.x) becomes a supported target in the Standard profile: real clock, client ID,
entropy, health vitals, a credentials store, MQTT-chunk and `fw_url` OTA, and examples built for it in CI
(design: Memory, concurrency and platforms; Examples).

**Architecture:** The core already compiles for the LX106 (`scripts/check_portability.sh`). This phase fills the
platform layer for it in `src/vl/platform/esp8266/`, the way `platform/esp32/` does for ESP32, and adds one portable
piece: `StreamHttp`, an `IHttpSource` over `INetStream`, so `fw_url` downloads work over any Arduino `Client`
(ESP8266 WiFi, W5500, TinyGSM) and are host-tested with a fake stream. MQTT runs over the existing
`StreamMqtt` + `ArduinoStream`.

**Tech Stack:** C++11; host Unity tests for `StreamHttp`; ESP8266 adapters build-verified (`nodemcuv2`).

## Decisions

- **Detection**: `VL_PLATFORM_ESP8266` = `defined(ESP8266)`. Single-threaded core, so `PlatformLock` stays
  `NullLock`; no `startTask()`.
- **Clock**: `micros64()` for uptime (no 32-bit wrap); `gettimeofday()` for UTC after `configTime()`, floor
  `VL_TIME_FLOOR_S` as on ESP32.
- **Entropy and ID**: `RANDOM_REG32` (hardware RNG); client ID from the station MAC (`wifi_get_macaddr`), so it is
  stable across boots like ESP32's.
- **Yield**: `platformYield()` lets blocking loops in the library feed the ESP8266 software watchdog
  (`yield()`), and give way on ESP32 (`vTaskDelay(1)`); no-op elsewhere.
- **Health**: free heap (`ESP.getFreeHeap()`), reset reason (`rst_info`), WiFi station link and RSSI through the
  SDK (`wifi_station_*`), so the library does not depend on the ESP8266WiFi library. Minimum free heap needs
  `UMM_STATS_FULL`, so it stays unknown.
- **Credentials**: `FsStore`, an `IKeyValueStore` over an Arduino `fs::FS` the application mounts (LittleFS): one
  file per key in a directory, written to a temporary file and renamed over the old one (LittleFS renames
  atomically), so a power cut leaves the old or the new value, never a torn one.
- **Firmware writer**: `Esp8266FirmwareWriter` over the core's `Update`. Size 0 (unknown) reserves the free sketch
  space and `end(true)` trims it. No rollback (eboot copies the image); the `IFirmwareWriter` defaults apply.
  `platformFirmwareWriter()` returns it.
- **`fw_url` downloads**: `StreamHttp(INetStream& plain, INetStream* secure = nullptr)`. HTTP/1.0 request, so
  servers never answer with chunked encoding (a chunked reply is refused). `Range: bytes=N-` to resume; 206 means
  resumed, 200 means restart. Up to 3 redirects (absolute or `/`-relative `Location`). Body ends at
  `Content-Length`, or at close when there is none. `open()` waits for the headers at most
  `VL_OTA_HTTP_TIMEOUT_MS`; `read()` reports a stall longer than that as an error. `https://` goes through
  `secure` with the `ITlsProvider` passed on (an Arduino TLS client ignores it; the app configures it), and is
  refused when `secure` is null. Platform-free, so ESP8266, STM32 and TinyGSM share it;
  `platformHttpSource()` stays null outside ESP32 and the app calls `ota.setHttp()`.
- **Persistence**: the ESP8266 core has no POSIX file API, so `FileOutboxStore` stays off there (the design lists
  `offline_persistence` for ESP32 and STM32 only).
- **Build matrix**: an example lists its boards in a `// Boards:` line (default `esp32dev`);
  `build_examples.sh` builds each on each, with the platform per board.
