# Phase 5d: TLS Provider and ATECC608 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** mTLS with the device key held in an ATECC608A/B, on ESP-IDF through esp-tls, and on Arduino-ESP32 through
an opt-in TLS client of our own. The Arduino path brings an in-house MQTT 3.1.1 transport over any Arduino `Client`
(WiFi, Ethernet, TinyGSM), which Phase 6 needed anyway.

**Architecture:** `ITlsProvider` gains `secureElement()`. Transports gain `validate()`, which `Client::begin()` calls so an
impossible setup fails at once with a log line instead of failing every connect. `EspMqtt` sets esp-tls's
`use_secure_element` when the build enables it. `StreamMqtt` is a platform-free `IMqttTransport` over a byte stream
(`INetStream`), with an MQTT 3.1.1 codec in core; `ArduinoStream<C>` adapts any Arduino `Client`. `AteccTlsClient` is an
Arduino `Client` that runs mbedTLS over another `Client` and signs the handshake with the ATECC608 through a small
driver of our own (`Atecc608`, over an `II2c` port), so it needs neither cryptoauthlib nor esp-tls support.

**Tech Stack:** C++11; host Unity tests for the codec, transport and ATECC protocol; ESP32 Arduino 2.0.x (mbedTLS
2.28) for the TLS glue, build-verified only (no hardware here).

## Decisions

- **Where each path works.**

  | Build | Secure element | How |
  | --- | --- | --- |
  | ESP-IDF 5.x, Arduino as IDF component | yes | `CONFIG_ESP_TLS_USE_SECURE_ELEMENT` + `espressif/esp-cryptoauthlib`; key slot 0 and the I2C address come from Kconfig |
  | Arduino-ESP32 2.0.x | yes, with `VL_ENABLE_ATECC608=1` | `StreamMqtt` + `AteccTlsClient` |
  | Arduino-ESP32 3.x (mbedTLS 3) | no | mbedTLS 3 hides the PK internals the key hook needs; `validate()` refuses it |

- **Refuse early.** `EspMqtt::validate()` rejects a secure element when the build lacks support, or a slot/address that
  differs from Kconfig (esp-tls has no runtime setting for them).
- **Certificate time.** `AteccTlsClient` checks validity itself in the mbedTLS verify callback, because the ESP32
  mbedTLS build has `MBEDTLS_HAVE_TIME_DATE` off: with a known clock, both dates; without one, only "expired before
  `VL_TIME_FLOOR_S`" (a not-before date cannot be judged without a clock, and refusing it would refuse every
  certificate issued after the firmware was built). esp-mqtt offers no verify hook: on ESP-IDF, enabling
  `CONFIG_MBEDTLS_HAVE_TIME_DATE` makes TLS wait for SNTP; on plain Arduino validity is not checked (documented).
- **MQTT transport.** Blocking `Client::connect()` (Arduino clients have no other kind; documented). Packet ids are
  the transport's; any number of QoS1 publishes in flight; inbound QoS1 is acknowledged at once; keep-alive PINGREQ
  every `keepAliveS`, link dropped after 1.5 × without traffic. A packet larger than the buffer is skipped and counted.
- **ATECC608 driver.** Wake, idle, Nonce (pass-through of the 32-byte digest), Sign (external message, key slot),
  GenKey (public key, to check the certificate matches), with CRC-16 (poly 0x8005, LSB first) and status packets.
  Retries on wake failure and on the "busy" status. Default address 0x60 (7-bit).
- **Heap.** mbedTLS allocates its session at connect time, as esp-mqtt's does; the library's own code stays heap-free.

### Task 4: ATECC608 driver
- [x] `II2c` port (`pal/I2c.h`): write, read (false on NACK), `wakePulse()`, `delayUs()`.
- [x] `se/Atecc608`: `sign(slot, digest, sig)` = wake, Random (seed update, as cryptoauthlib does), Nonce pass-through
  into the message-digest buffer, Sign external from that buffer, idle; `publicKey(slot, pub)` = GenKey mode 0. Responses
  polled: wait the command's maximum execution time, then poll every 2 ms up to 2.5 s. Up to 3 attempts per operation
  on a failed wake, no response, bad CRC, or status 0xFF / 0xEE / 0x11 / 0x05; other error statuses fail at once.
- [x] `ecdsaDer()`: raw r || s to an ASN.1 ECDSA-Sig-Value.
- [x] Tests with a fake chip: golden command bytes (CRC checked against an independent implementation), flows, busy
  polling, wake retries, a chip left awake, error and transient statuses, bad CRC, no chip, DER encodings.

### Task 5: Arduino streams, examples, docs, gate

Refinements found while writing Task 4:

- `INetStream::connect(host, port, tls)` and `INetStream::validate(tls)` replace `secure()` / `secureElement()`: a
  stream reads the CA, certificate and key slot from `Config::tls`, the single source of truth, and can refuse a
  missing certificate at `begin()`.
- `AteccTlsStream` (was `AteccTlsClient`) is an `INetStream` running mbedTLS over any Arduino `Client`. It is compiled
  wherever mbedTLS 2.x ships with the Arduino core (`VL_HAVE_ATECC_TLS`), so `VL_ENABLE_ATECC608` is dropped; unused, it
  is discarded by the linker. At connect it checks that the certificate's public key is the chip's.
- `ArduinoStream` wraps `Client&` (any Arduino target) and is plain: TLS done inside the client (SSLClient) is the
  application's, with `Config::tls` null.
- `core/CertTime`: date to epoch and the validity policy, host-tested.
